# 02 · 数据库表结构、接口定义与数据流说明

> 适用范围：`lottery-analyzer/server/`（Python 标准库 HTTP 服务 + SQLite）。Web 端与 Android 端共用以下同一套接口，不另建后端。

## 1. 数据库表结构（SQLite，单文件 WAL）

数据库默认路径：`server/data/lottery.db`（可用环境变量 `LOTTERY_DB` 覆盖）。DDL 见 `server/lottery_server/db.py` 的 `SCHEMA`。

### 1.1 `draws` —— 开奖历史

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | |
| game | TEXT NOT NULL | `ssq` 双色球 / `dlt` 大乐透 |
| issue | TEXT NOT NULL | 期号（字符串，保持官方原样，如 `2026112`、`26112`） |
| draw_date | TEXT NOT NULL | 开奖日期 `YYYY-MM-DD` |
| reds | TEXT NOT NULL | 前区号码 JSON 数组，升序，如 `[1,5,12,22,30,33]` |
| blues | TEXT NOT NULL | 后区号码 JSON 数组，如 `[7]` 或 `[3,9]` |
| source | TEXT NOT NULL | 数据来源说明（官方接口中文名，见 §3.1） |
| fetched_at | TEXT NOT NULL | 入库时间（ISO） |

约束：`UNIQUE(game, issue)` —— 同一彩种同一期号唯一，重复同步幂等（`upsert_draws` 先查后插/改，重复拉取计为 update）。

### 1.2 `sync_log` —— 同步审计

| 列 | 说明 |
|---|---|
| id, ts | 自增、时间 |
| game / mode | 彩种 / `incremental`·`full` |
| source | 来源 URL 说明 |
| ok | 0/1（失败同样记录，保证可追溯） |
| message | 成功摘要或错误信息 |
| fetched / inserted / updated | 拉取 / 新增 / 更新条数 |

### 1.3 `scratch_samples` —— 刮刮乐样本与验证闭环

| 列 | 说明 |
|---|---|
| id, created_at | 自增、创建时间 |
| image_path / roi_path | 原图与 ROI 裁剪图（相对 DATA_DIR 存储，经 `/media/` 提供） |
| ticket_type / ticket_type_conf | 识别票种 id 及置信度（用户 hint 命中时 conf=1.0） |
| ocr_engine / ocr_text | `tesseract` 或 `unavailable`（服务端 OCR 未安装时） |
| predicted_rank / predicted_amount | 模板匹配出的奖级与金额 |
| confidence | 合成置信度 = 0.4×票种 + 0.35×OCR + 0.25×模板（round 4） |
| needs_review / review_reason | 是否需人工复核 / 原因（`no_ticket_type`·`ocr_unavailable`·`low_confidence`·`no_template_match`） |
| actual_rank / actual_amount | 用户录入的实际结果 |
| match_status | `pending` 待录入 / `match` 命中 / `mismatch` 不符 / `review` 人工复核 |
| verified_at / device / note | 验证时间 / 设备来源 / 备注（Android 端本地预测写入 note，保证可追溯） |

### 1.4 `model_runs` —— 训练与回测档案

| 列 | 说明 |
|---|---|
| id, created_at | 运行号、时间 |
| game / model_name / feature_version / seed / test_ratio / window | 训练配置（可复现参数） |
| train_samples / test_samples | 样本量（样本=（期,号码）对） |
| metrics_json | `{"auc":..,"log_loss":..,"brier":..}`（round 4） |
| report_json | 完整回测报告（含权重、指纹、方法说明、免责声明） |
| artifact_path | `server/models/run_{id}.json`（权重归档） |
| dataset_fingerprint | sha256([[issue,date,reds,blues]])，数据集指纹 |

## 2. 接口定义（全部 JSON；错误统一 `{"error": "..."}`）

通用映射：`ValueError→400`、`SourceError→502`（上游官方接口不可达）、OCR 组件缺失→503。

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/health` | – | 存活检查 `{status, games, version}` |
| POST | `/api/draws/sync` | body `{game, mode?, limit?}` | 官方增量/全量同步，返回 `{fetched, inserted, updated, errors, total_in_db, source}` |
| GET | `/api/draws` | `game, page, page_size≤200` | 分页开奖（倒序）`{rows, total, page, page_size}` |
| GET | `/api/draws/synclog` | `limit=20` | 同步审计日志 |
| GET | `/api/stats/frequency` | `game, window(0=全部)` | 频率：`rate = count / draw_count`（round 4） |
| GET | `/api/stats/omission` | `game` | 遗漏：`current`=距最近开出期数；`max`=历史最长间隔；`avg`=历史间隔均值（从未开出则 `avg=null`） |
| GET | `/api/stats/trend` | `game, last_n≤200` | 近期走势（最新在前，附 front_max/back_max 供网格渲染） |
| POST | `/api/model/train` | body `{game, seed=7, test_ratio=0.2, window=30}` | 训练+回测，返回精简报告（不含权重；权重在详情里） |
| GET | `/api/model/runs` | `game, limit` | 历史运行（仅 metrics） |
| GET | `/api/model/runs/{id}` | – | 完整报告（含 weights，供纯 Kotlin 推理） |
| POST | `/api/model/predict` | body `{game, run_id?, top_k?}` | 基于最新（或指定）运行输出下期 Top-K 概率 + 免责声明 |
| POST | `/api/scratch/samples` | multipart：`image`（必填）+ `ticket_type_hint/device/note` | 服务端识别落库，返回样本（含 `needs_review` 判定） |
| GET | `/api/scratch/samples` | `status?, limit` | 样本列表（`image_url/roi_url` 指向 `/media/`） |
| POST | `/api/scratch/samples/{id}/verify` | body `{actual_rank?, actual_amount?, note?}` | 录入实际结果：无预测→`review`；有交集逐字段比对→`match/mismatch`；无交集→`review` |
| GET | `/api/scratch/accuracy` | – | `{total, by_status, auto_verified{total,match,mismatch,accuracy}, by_ticket_type}` |
| GET/PUT | `/api/scratch/profiles` | – | 读取/整体保存票种模板 `profiles.json` |
| GET | `/media/*` | – | 图片（防路径穿越） |
| GET | `/*` | – | Web 静态页（`web/` 目录） |

## 3. 数据流

### 3.1 开奖数据流（官方数据源，不伪造）

```
官方接口 ──HTTP(UA/Referer)──► sources.parse_* ──make_row 校验──► db.upsert_draws（UNIQUE 去重）
                                                                      │
                                        失败/成功均写 sync_log（可追溯） ◄┘
```

- 双色球（`ssq`）：中国福利彩票发行管理中心官网开奖公告接口 `findDrawNotice`（域名 www.cwl.gov.cn）。接口要求特定 `User-Agent` 与 `Referer`，已内置；不可达时抛 `SourceError`（HTTP 502），**不返回任何合成数据**。
- 大乐透（`dlt`）：中国体育彩票官方 `webapi.sporttery.cn/getLotteryInfo List`，具体为 `webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry?gameNo=85&provinceId=0&pageSize=…&isVerify=1&pageNo=…`（实测可用，返回 `value.list[]`，`lotteryDrawResult` 空格分隔前5后2）。

### 3.2 统计 → 模型 → 预测

```
draws ─► stats.frequency/omission（纯 SQL+Python 计算，逐条可核对）
      └► model.build_dataset（逐（期,号码）样本；特征 freq_omit_v1 = [窗口频次, 遗漏/窗口, 近3期命中/3, 偏置]）
             └► fit_logistic（标准化 + L2 全批量梯度下降，固定 seed，确定性输出）
                    └► train_and_backtest（按时间切分：最近 max(3, round((n-window)×test_ratio)) 期为测试集）
                           └► 指标 AUC / LogLoss / Brier + 模拟（每期选 Top-K，对比随机基线）
                                  └► report（含方法说明、数据指纹、免责声明）落库 + artifacts/run_{id}.json
predict_next：读取 report.weights + 最新 draws 构特征 → sigmoid → Top-K（仅供学习参考）
```

### 3.3 刮刮乐验证闭环

```
拍照/相册 ─► 票种识别（宽高比±15%窗 + 主色距离打分；hint 命中则 conf=1.0）
        ─► ROI 裁剪（模板相对坐标）
        ─► OCR（服务端 tesseract chi_sim；Android 端 ML Kit 中文；不可用→503/needs_review）
        ─► 模板匹配（prize_table；唯一命中 conf=1.0，多命中取最大金额 conf=0.5）
        ─► confidence = 0.4×票种+0.35×OCR+0.25×模板；<0.60 或关键环节缺失 → needs_review
        ─► 用户录入 actual_rank/actual_amount ─► match/mismatch/review ─► accuracy 聚合（闭环）
```

Android 端补充：本地识别用于即时预览；服务端可能未装 tesseract，其落库记录会标 `needs_review=ocr_unavailable`。为不丢失本地结论，Android 上传时把本地预测写入 `note`（如 `mlkit预测:100元档 conf=0.71`），两类记录均可追溯。
