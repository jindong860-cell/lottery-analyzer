# 03 · 安装步骤、测试用例与运行验证清单

> 环境说明：本项目在受限沙箱中开发（无网络运行环境、无 Android SDK、PowerShell 不可用），所有测试与构建命令以「用户本机可执行」为标准给出，全部命令均经过代码级自检核对。

## 1. 后端（Python ≥3.10）

**一键方式（Windows，推荐）**：双击 `server/启动后端.bat` —— 自动建虚拟环境、装依赖、起服务并打开 `http://127.0.0.1:8000/`。

手动方式：

```bash
cd lottery-analyzer/server
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt          # numpy + Pillow 必装；pytesseract 可选
python run_server.py                     # 默认 0.0.0.0:8000；环境变量 LOTTERY_HOST/PORT/DB/DATA 可覆盖
```

> 注意：Web 页面必须由后端托管访问（`http://127.0.0.1:8000/`）。**直接双击 `web/index.html`（file://）会导致所有接口调用失败**，页面顶栏会给出明确指引。

- 服务端 OCR（可选）：安装 [Tesseract OCR](https://github.com/tesseract-ocr/tesseract)（Windows 下载 UB-Mannheim 安装包），确保 `tesseract` 在 PATH 中，并包含中文语言包 `chi_sim`。未安装时刮刮乐自动降级为「人工复核」，其余功能不受影响。
- 单元/集成测试（无网络依赖，内置夹具）：

```bash
cd lottery-analyzer/server
python -m unittest discover -s tests -v
```

预期：5 个测试文件全部 OK（数据层去重/审计、官方解析器夹具、统计手算对照、模型确定性+可复现回测、HTTP 全链路 15 步集成）。

## 2. Web 端（零构建）

浏览器打开 `http://127.0.0.1:8000/`（由后端同源托管 `web/` 目录）。首次使用点「首次全量」拉取 ≤1000 期历史，此后「增量同步」即可。

## 3. Android 端（Kotlin + Compose）

1. 安装 Android Studio（Koala/2024.1 及以上，含 JDK 17）。
2. `File → Open` 打开 `lottery-analyzer/android/`，等待 Gradle 同步（首次会自动下载 AGP 8.5.2 / Kotlin 2.0.20 等依赖；项目已带 `settings.gradle.kts` 版本目录声明，无需额外配置）。
3. 模拟器默认后端地址 `http://10.0.2.2:8000/`（即宿主机）；真机请在 App「设置」页改为电脑局域网 IP（如 `http://192.168.1.100:8000/`），并保持手机与电脑同一网络。
4. 构建 APK：
   - 方式 A（推荐）：Android Studio 菜单 `Build → Build App Bundle(s)/APK(s) → Build APK(s)`，产物在 `android/app/build/outputs/apk/debug/app-debug.apk`。
   - 方式 B（一键脚本）：双击 `android/build_apk.bat`（自动用 gradlew 或本机 Gradle 8.7+ 生成 wrapper 并构建）。
   - 方式 C（云端构建，本机无 Android SDK 时）：把 `lottery-analyzer` 推送到 GitHub，仓库已带 `.github/workflows/build-apk.yml`，在 Actions 页手动运行 `build-apk`，完成后从 Artifacts 下载 `lottery-analyzer-debug-apk`。
   - 说明：仓库内不提交 Gradle wrapper 二进制（`gradle-wrapper.jar`），因此命令行构建前需先生成 wrapper——这是有意的，避免提交平台相关二进制文件。
5. 安装：`adb install app-debug.apk` 或直接将 APK 拷入手机安装（需允许未知来源）。

## 4. 测试用例清单（与 `server/tests/` 对应）

| 文件 | 类型 | 关键用例 |
|---|---|---|
| `test_db.py` | 单元 | upsert 幂等去重（首插 ins=2/upd=0 → 重插 ins=1/upd=1）；样本生命周期与 accuracy 聚合（auto_verified 只统计有预测且已判定的样本）；model_runs 存取往返；sync_log 记录 |
| `test_sources.py` | 单元 | SSQ/DLT 官方响应夹具解析（含 1 条坏记录不中断，errors=1）；make_row 参数校验（彩种/个数/范围/去重/日期）；分页拉全（假 fetcher 两次同步：首插 2、重插 inserted=0/updated=2，库内恒为 2）；SourceError 落日志后上抛；未知彩种报错 |
| `test_stats.py` | 单元 | 5 期固定开奖手算对照：频率（如 num1=3/5=0.6、窗口=2 时 num13=2）；遗漏 current/max/avg（含「从未开出」avg=None）；trend 倒序；未知彩种 ValueError |
| `test_model.py` | 单元+集成 | 高斯可分数据 AUC>0.95 且两次训练逐位一致（确定性）；退化数据 auc=None；样本不足/参数越界报错；120 期确定性偏置数据端到端回测可复现（metrics 全等、test_draws=22、hit_rate_at_least_1=1.0、artifact 落盘、predict_next Top-5） |
| `test_api.py` | 集成 | 临时端口起真实 HTTP 服务 + 临时目录：健康检查→同步→分页→三项统计→400 校验→训练（无权重泄露）→运行详情（含权重）→预测→刮刮乐上传（100×200 纯红图，无 tesseract 时 needs_review）→媒体回取→验证闭环（review→match→改金额 mismatch）→accuracy→profiles GET/PUT→静态页→404 |

## 5. 逐模块运行验证清单（用户自测）

| 模块 | 步骤 | 预期 |
|---|---|---|
| 数据同步 | Web「开奖数据」→ 大乐透「首次全量」 | 提示新增 ≥900 期；列表倒序展示；同步日志有 ✅ 记录 |
| 数据守恒 | 再次「增量同步」 | 提示「新增 0，更新 N」（N=新增期数），总期数不变 |
| 官方源容错 | 断网后同步 | 界面提示失败；`/api/draws/synclog` 出现 ❌ 记录；不产生假数据 |
| 统计 | 「统计分析」窗口=100 → 计算 | 柱图与表格一致；遗漏表含 当前/最大/平均 |
| 训练回测 | 「模型」默认参数训练 | 返回运行号与 AUC/LogLoss/Brier；报告含数据范围、指纹、免责声明 |
| 可复现性 | 同参数再训练一次 | metrics 完全一致（seed 固定、数据指纹一致） |
| 预测 | 「基于最新运行预测下期」 | Top-K 高亮 + 完整免责声明（随机性提示） |
| 刮刮乐（无 tesseract） | 上传任意票面照片 | 样本入库，状态「⚠人工复核」，原因 `ocr_unavailable`；`/media/` 可回看原图与 ROI |
| 刮刮乐（装 tesseract 后） | 上传清晰票面 | OCR 文本非空；命中奖级时给出预测与置信度 |
| 验证闭环 | 「录入实际结果」 | 预测一致→✅命中；不一致→❌不符；无预测→⚠复核；准确率随之更新 |
| Android | 安装 APK → 设置页测连 | 健康检查 ✅；开奖/统计/模型与 Web 数据一致 |
| Android OCR | 拍照识别 | 本地 ML Kit 预览结果 + 上传后样本可见（note 含本地预测） |

## 6. 已知限制与替代方案（均已在方案内说明理由）

1. **沙箱内无法运行 Gradle/APK 构建**：APK 需在用户本机 Android Studio 构建（§3 方式 A），不影响代码完整性。
2. **双色球接口需特定 UA/Referer**：已在 `sources.SSQ_HEADERS` 内置；若官方临时调整导致 502，属预期容错（不伪造数据）。
3. **服务端 OCR 为可选组件**：缺 tesseract 时刮刮乐走「人工复核」闭环（这正是需求中的降级要求），Android 端用 ML Kit 端侧识别补足。
4. **Lite 模式预测仅基于逻辑回归**：刻意选择——参数量小、完全可复现、结果可解释（附方法与数据指纹），不引入不可控的黑盒依赖。
