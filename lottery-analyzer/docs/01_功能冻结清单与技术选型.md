# 幸运分析台（Lottery Analyzer）— 功能冻结清单与技术选型 v1.0（已冻结）

> 冻结原则：本清单逐条对应用户原始需求，**不新增、不删减**。如需变更，须先修订本文件再动代码。

## 1. 总体形态

单一后端服务承载：开奖数据采集、本地数据库、统计分析、模型训练与回测、刮刮乐识别管线、REST API、网页版静态托管。
Android 原生 App 与网页版（Web SPA）**共享同一套 REST 接口**，所有功能整合在各自应用内，不拆分独立工具。

```
                ┌────────────────────────────┐
                │      后端（Python 单进程）   │
                │  stdlib HTTP + SQLite 单文件 │
                │  numpy 模型/回测  Pillow 图像 │
                └──────┬─────────────┬───────┘
          同一 REST API │             │ 同一 REST API
        ┌───────────────┴──┐       ┌──┴────────────────┐
        │ Android App       │       │ 网页版（同源托管）  │
        │ Compose+Room      │       │ 原生 HTML/JS SPA   │
        │ ML Kit 本地 OCR   │       │ 服务端 OCR(可选)    │
        └───────────────────┘       └───────────────────┘
```

## 2. 功能冻结清单

| 编号 | 功能 | 验收口径 |
|---|---|---|
| F1 | 开奖数据接入：双色球（福彩官网接口）+ 大乐透（体彩官方 webapi）；历史数据库；增量更新；按（彩种,期号）唯一去重 | 同一期重复拉取库中仅一行；无网络/接口变更时报错而非伪造数据 |
| F2 | 统计分析：频率（前区/后区，可设统计窗口）、遗漏（当前/最大/平均）、走势（最近 N 期） | 每项统计附计算公式说明（代码注释 + docs/02） |
| F3 | 模型训练与回测：按时间序切分训练/测试集；逻辑回归（numpy 自实现）；输出 AUC / LogLoss / Brier + Top-K 命中模拟 vs 随机基线；固定配置 + 数据指纹 → 可复现 | 两次相同参数训练指标完全一致；报告含方法、样本量、指纹、随机性声明 |
| F4 | 刮刮乐闭环：上传/拍照未刮票图 → 票种识别 → OCR → ROI 裁剪 → 奖级模板匹配 → 置信度不足提示人工复核 → 用户录入实际结果比对 → 样本与验证结果全部持久化、可查准确率 | 每张样本可追溯（原图、ROI 图、OCR 原文、置信度、复核原因、比对结果）；准确率页可统计 |
| F5 | 共享后端：全部功能以 REST API 暴露；网页版由同一服务同源托管 | Android 与网页调用完全相同的接口路径 |
| F6 | Android 原生 App（Compose）：整合 F1–F4 全部功能；Room 离线缓存；相机/相册采集；ML Kit 本地 OCR；服务器导出权重的本地轻量推理 | 一条 `gradlew assembleDebug` 产出可安装 APK |
| F7 | 网页版 SPA：数据同步/列表、统计、模型训练/回测/预测、刮刮乐上传-录入-准确率、票种模板校准（JSON） | 浏览器打开 `http://<主机>:8000` 即用，无构建步骤 |
| F8 | 打包与交付：Gradle 工程出 APK；网页部署说明；安装步骤/测试用例/逐模块验证清单 | 见 docs/03 |

## 3. 明确不做（未确认不新增）

多用户/账号体系、自动购彩或投注、消息推送、云服务依赖、iOS、本期新增其他彩种（七乐彩/快乐8 等——数据源层已按插件式预留，但本期不接入）、票据图像云存储（仅本地磁盘）。

## 4. 技术选型与依据

| 层 | 选型 | 依据 |
|---|---|---|
| 后端服务 | Python 3.10+ 标准库 `http.server`（ThreadingHTTPServer） | 个人单机使用：零框架、零部署、无 Node/Docker 依赖；单用户并发足够；供应链最小化 |
| 本地数据库 | SQLite（stdlib `sqlite3`，WAL 模式，单文件 `server/data/lottery.sqlite3`） | "本地数据库"要求的最直接落地；单文件易备份；个人写入并发低 |
| 数值计算 | numpy（自实现逻辑回归、回测指标） | 特征仅 4 维、样本数千级，无需 sklearn/TF；全批量 GD 无任何随机成分，可复现性最强 |
| 图像处理 | Pillow（票种识别、ROI 裁剪、模板比对输入） | 纯 Python 轮子安装简单；能力足够覆盖本管线 |
| 服务端 OCR | pytesseract + Tesseract（**可选**，未安装自动降级为"人工复核"） | Tesseract 需系统级安装，故设计为可选增强；Android 端 ML Kit 为主识别路径 |
| Web 前端 | 原生 HTML/CSS/JS 单页（无构建链），Canvas 手绘图表 | 与后端同进程同源托管，浏览器即用；避免引入打包工具链 |
| Android | Kotlin 2.0 + Jetpack Compose(M3) + Navigation-Compose；Retrofit/OkHttp(Gson)；Room(KSP)；ML Kit text-recognition-chinese v2（本地离线 OCR）；Coil | 官方主推栈；ML Kit 免费离线、中文识别质量好；Gson 免注解处理器；Room 为 Android 本地数据库标准 |
| 轻量 ML 集成 | 服务器训练 → 导出权重 JSON → Android 纯 Kotlin 推理 | 模型仅 4 维特征逻辑回归，权重仅 13 个浮点数，引入 TFLite 运行时（约 3MB+）不成比例；文档注明未来复杂模型再切换 TFLite |

## 5. 官方数据源（附来源，仅此两家）

| 彩种 | 接口 | 来源说明 |
|---|---|---|
| 双色球 | `https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice?name=双色球&issueCount=N`（需浏览器 UA + Referer 头） | 中国福利彩票发行管理中心官网（www.cwl.gov.cn）开奖公告接口，页面入口 `/ygkj/wqkjgg/ssq/` |
| 大乐透 | `https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry?gameNo=85&provinceId=0&pageSize=N&isVerify=1&pageNo=P` | 中国体育彩票官方 webapi（webapi.sporttery.cn），大乐透 gameNo=85；本方案开发期已实测可用 |

接口随时可能变更：变更/不可达时后端抛出明确错误并写入同步日志，**绝不伪造数据**。

## 6. 风险、限制与替代方案（约束要求：给替代方案而非省略）

| 限制 | 替代方案与理由 |
|---|---|
| 本沙箱无 Android SDK/Gradle，无法直接产出 APK 二进制 | 交付完整可编译 Gradle 工程；用户在 Android Studio 打开自动拉取 Gradle 8.7 与依赖，`assembleDebug` 一键出 APK。理由：APK 构建必须依赖 Android SDK，属环境限制，代码层面无省略 |
| 服务器端 OCR 依赖 Tesseract 系统安装 | 未安装时自动降级：仍完成票种识别 + ROI 裁剪 + 样本入库，标记 `needs_review` 由用户人工录入；Android 端 ML Kit 为全功能主路径 |
| 双色球官网接口对请求头敏感（无 UA/Referer 可能 403/404） | 运行时代码已带浏览器头；仍失败时错误信息含来源 URL 便于核对，并写入同步日志 |
| Android 相册图片可能带 EXIF 旋转信息 | 服务器端用 `ImageOps.exif_transpose` 校正；Android 端 Photo Picker 返回已解码朝向的 Bitmap（API 26+ 主体机型行为一致），残留个案在样本页可人工纠正 |
| Android 后台保活受限，无法可靠定时增量更新 | 采用前台手动"一键同步"（单用户场景秒级完成），不做后台守护进程 |
| 彩票开奖随机性 | 所有模型/预测/回测接口与页面强制附免责声明；回测含"随机基线对照"，用数据呈现模型相对随机的真实增益 |

## 7. 合规声明（内置到产品）

1. 开奖数据仅来自官方公开接口/页面，不伪造、不采用第三方聚合站。
2. 彩票开奖为独立随机事件：历史统计与模型回测不改变未来开奖的随机性；预测结果仅供方法学习与数据参考，**不构成投注建议**（声明内置：API 响应字段、Web 页脚、App 模型页）。
3. 刮刮乐识别置信度不足时强制人工复核；全部样本与验证结果持久化，保证可追溯。
